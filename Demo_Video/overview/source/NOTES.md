# Sources and animation notes

## Source material

The visual is based on **page 1 of the user-supplied `Overview_fig.pptx`**. The original slide measures 510.25 × 269.25 points; only the empty lower margin is removed for the 510.25 × 240 display area. The original robot poses, table, panels, labels, training views and arm illustration are retained as a compressed image plate. Selected original arrows and phase wheels were removed from a working copy and redrawn as native SVG in the same slide coordinates. No replacement robots or experimental images were generated.

The uploaded `Demo_Video.zip` did **not** contain the referenced `paper/` directory, paper PDF, LaTeX source or Archify package. The supplied old README claimed that paper sources had been read; that claim was not independently verified and is not relied on here.

## What the motion means

- The complete base arrows remain visible. Travelling light bands and packets indicate the authored direction of information flow. Inactive branches recede but are not deleted.
- The source scene remains a fixed snapshot: **A / Strike, B / Clear**. The role badges are not relabelled as though the photographs were a real robot replay.
- Strike adds an illustrative ball passage, contact ring and seven-joint highlight. Clear adds outward chevrons and a clearance halo. These are graphic overlays, not tracked robot motion.
- Task phases cycle through the five names shown in the source. The pointer, reference highlight, skill outline, branch flow and action-selector readout share one state. Selecting a phase holds the animation; Play resumes it.
- The short reference scan is a visual explanation, **not a motion-matching algorithm running in the browser**. Phase durations, transition order and contact timing are presentation settings, not measured control timing. The proposed phase-to-skill correspondence should be checked against the missing paper before publication.

## Archify integration

The separate deployment relationship map is generated by the actual `tt-a1i/archify` renderer from a typed data-flow specification, with trace animation and guided views. Its deterministic validation/delivery receipts are kept next to the generated HTML. The pinned source revision is recorded in the GitHub workflow.

The overview page is a custom, slide-aligned SVG presentation. It is **not** falsely described as a stock Archify rendering: pictorial fidelity, the moving ball, clearance cues and phase-to-pose matching require custom JavaScript. Archify handles the additional explorable semantic map.

## Playback and accessibility

One `requestAnimationFrame` clock drives all effects. Pause freezes the clock and signal positions. Reduced Motion removes moving overlays while preserving static paths, labels and manual phase selection. Hidden tabs stop rendering. Controls work with buttons, phase-wheel nodes and keyboard shortcuts: Space, Left/Right and R. Browser print temporarily restores the full overview.

## Verification scope

`verification/browser.json` records Chromium tests performed with the exact website HTML, CSS, JavaScript and image inlined into `page.set_content`. This was necessary because the execution environment blocks both local HTTP and file URL navigation. No claim is made that local URL loading or GitHub Pages delivery was tested by that run. The test checks phase matching, live signal movement, frozen playback, reduced motion, view switching, console errors and overflow at six viewport sizes. Screenshots were also inspected separately.
